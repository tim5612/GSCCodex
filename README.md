# 現場商品標籤 OCR 測試

這是一套在手機拍照當下協助辨識商品型號的測試系統。現場人員先人工選擇品牌，每件商品拍照後只執行一次型號 OCR；序號不做 OCR，一律由實體一維條碼機輸入，確認無誤後才產生 QR Code。

> 目前後端辨識規則仍以既有的 LG 白色標籤型號 OCR 為主；其他品牌需要拍照樣本才能繼續校準。無論品牌為何，序號都不會進入 OCR 流程。

## 本次更新內容

- 新增拍攝前的品牌選擇畫面。
- 新增 LG、Panasonic、Hitachi、Mitsubishi、Sony、Samsung、HAWRIN／華菱及其他品牌的專用 UI。
- 每個品牌具有不同的取景框比例、欄位名稱與拍攝提示。
- 支援手機相機拍攝，以及從手機相簿／檔案選取照片；相機與相簿畫面的綠框都能拖曳四角調整寬度與高度，相簿照片另可單指移動及雙指縮放。
- 拍照後顯示保存的照片，讓人員核對或修正機器型號，再以實體條碼機輸入序號。
- 標籤定位或 OCR 失敗時不會中斷流程，仍會保存原始照片並允許人工輸入。
- 產生結果時會保存所選品牌、機器型號、序號、日期與輸入方式。
- 完成後可選擇「同品牌下一件」，不必每次重新選擇品牌。

## 品牌拍攝模板

| 品牌 | 現場主要對準內容 | 預期欄位／關鍵字 |
| --- | --- | --- |
| LG | 橫向白色標籤 | 左側型號、右側 `S/NO` |
| Panasonic | 直向或重複排列的標籤 | `機種名稱`、`製造號碼` |
| Hitachi | 機身銘牌、條碼標籤 | `MODEL`／`製造番号`、SKU 或長條碼 |
| Mitsubishi | 機身銘牌 | `MODEL`、`SERIAL` |
| Sony | 原廠標籤，不要只拍空白保證卡 | 型號、`機號` |
| Samsung | 原廠產品標籤 | `Model Code`、`S/N` |
| HAWRIN／華菱 | 外箱或機身標籤 | 型號、製造號碼 |
| 其他品牌 | 完整拍下品牌、型號與序號區域 | 人工確認欄位 |

同品牌的標籤版型通常相近，因此 UI 以品牌為單位建立模板；現場測試時請特別記錄同品牌中是否仍有不同版型。

## 在另一台 Windows 10 測試機安裝

### 1. 複製專案

將整個專案資料夾複製到測試機。不要沿用另一台電腦建立的 `.venv`，請在測試機重新建立虛擬環境。

### 2. 安裝 Python

建議安裝 **64 位元 Python 3.12**，並確認命令提示字元或 PowerShell 可以執行：

```powershell
py -3.12 --version
```

本專案固定使用 CPU 版 PyTorch 2.5.1。請優先使用 Python 3.12，避免新版 Python 與目前固定套件版本不相容。

### 3. 建立環境及安裝套件

在 PowerShell 切換到專案資料夾後執行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

安裝 PyTorch、OpenCV 與 EasyOCR 需要一些時間及磁碟空間。第一次安裝及第一次啟用 EasyOCR 時，測試機需要能連上網路以下載套件與英文辨識模型；正式到無網路現場前，請先完成安裝並實際啟動一次。

## 啟動服務

最簡單的方式是雙擊：

```text
啟動OCR服務.bat
```

批次檔會使用專案內的 `.venv`、啟用 EasyOCR，並啟動 Port 5000。若 Port 5000 已有程式占用，批次檔會先停止該監聽程式。

也可以在 PowerShell 手動啟動：

```powershell
$env:ENABLE_EASYOCR="1"
.\.venv\Scripts\python.exe app.py
```

在測試機本機開啟：

<http://127.0.0.1:5000>

停止服務可關閉執行視窗、按 `Ctrl+C`，或雙擊：

```text
關閉OCR服務.bat
```

## 手機連線方式

1. 手機與測試機連接同一個 Wi-Fi 或區域網路。
2. 在測試機執行 `ipconfig`，找到目前網路介面的 IPv4 位址，例如 `192.168.1.25`。
3. 在手機瀏覽器開啟 `http://192.168.1.25:5000`。
4. Windows 防火牆詢問時，允許 Python 使用「私人網路」。

部分手機瀏覽器會禁止一般 HTTP 區網網址使用網頁內即時相機。遇到「無法啟動相機」時，請按畫面上的「相簿」按鈕，改用手機原生相機／檔案選擇器拍攝或選圖，仍可完成這次測試。若未來要讓區網手機穩定使用即時取景框，需要把服務改為 HTTPS。

## 現場測試流程

1. 開啟手機頁面，人工選擇品牌。
2. 依該品牌的提示與取景框拍下清楚的機器型號；若從相簿選圖，先拖曳、縮放照片，確認型號位於綠框後再送出。
3. 確認檢查畫面有顯示本次保存的照片。
4. 對照照片核對或修正機器型號，再用實體一維條碼機輸入序號。
5. 勾選確認後產生 QR Code。
6. 使用「同品牌下一件」繼續，或返回更換品牌。
7. 回到測試機檢查 `data/captures` 是否留下完整記錄。

建議每次發現問題時記下：品牌、產品種類、標籤版型、手機型號、瀏覽器、橫拍／直拍、拍攝距離、光線，以及失敗畫面的狀況。這些資料會用來調整下一版品牌模板。系統可直接接收 iPhone 的 HEIC 相簿原檔。

## 保存資料位置

每次拍攝會建立一個獨立資料夾：

```text
data/
└─ captures/
   └─ YYYY-MM-DD/
      └─ <capture-id>/
         ├─ original.jpg       原始上傳照片
         ├─ rectified.png      定位／校正後照片；定位失敗時為原圖副本
         ├─ model-region.png   型號候選區域（有產生時）
         ├─ enhanced.png       OCR 強化影像（有產生時）
         ├─ capture.json       品牌、OCR 候選與拍攝處理記錄
         ├─ qr.png             產生的 QR Code
         └─ result.json        最後確認的型號、序號、日期與品牌
```

QR Code 目前內容格式為：

```text
機器型號|序號|日期
```

品牌會保存在 `capture.json` 與 `result.json`，目前不會寫入 QR Code 內容。

## 目前辨識狀態與限制

- 後端目前只有既有的 **LG 白色標籤機器型號** OCR 邏輯。
- 序號刻意不做 OCR，只接受實體一維條碼機輸入；其他品牌目前尚未建立正式辨識規則。
- OCR 或白色標籤定位失敗時，系統會保留照片並讓人員人工輸入，不會直接放棄該筆資料。
- 系統只會統一大小寫、空白與破折號，不會擅自互換 `8/B`、`0/O`、`1/I`、`5/S` 等易混淆字元。
- 所有 OCR 結果都必須由現場人員對照照片確認。
- 手機現場拍照通常會送出 JPEG；從相簿匯入的 HEIC 會由伺服器自動解碼。

## 現場驗收清單

- [ ] 每個品牌都能進入正確的專用拍攝畫面。
- [ ] 取景框方向、比例與標籤實際版型接近。
- [ ] 即時相機不可用時，仍能用相簿／原生相機完成拍攝。
- [ ] 拍攝後能看到正確的保存照片。
- [ ] 型號可核對或修正，序號欄會保持空白等待實體條碼機輸入。
- [ ] 未勾選人工確認時，不能產生 QR Code。
- [ ] QR Code 能正常產生及顯示。
- [ ] 「同品牌下一件」及「更換品牌」流程正常。
- [ ] `data/captures` 中有保存照片、JSON 記錄與 QR Code。

## 常見問題

### 雙擊啟動後顯示找不到 Python

確認專案內已建立 `.venv`，並且存在 `.venv\Scripts\python.exe`。若不存在，重新執行「建立環境及安裝套件」的三個命令。

### 手機無法連線

確認服務仍在執行、手機與電腦在同一網路、網址使用正確 IPv4 位址，並允許 Windows 私人網路防火牆。部分訪客 Wi-Fi 會隔離裝置，這種網路下手機無法連到電腦。

### 手機無法開啟即時相機

先允許瀏覽器相機權限。若仍失敗，通常是瀏覽器限制 HTTP 網頁使用相機；請使用「相簿」按鈕改由手機原生介面拍攝。這不影響照片保存、人工核對與 QR Code 測試。

### OCR 沒有讀出結果

先確認使用 `啟動OCR服務.bat`，或啟動前已設定 `ENABLE_EASYOCR=1`。目前只有 LG 白色標籤型號有既有辨識邏輯；其他品牌請保留照片作為後續規則設計的測試資料。序號不做 OCR，請直接使用實體條碼機輸入。
